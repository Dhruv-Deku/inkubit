Summary

Inkubit is a quantum lab in the browser. Meta's models read, plan and propose, and exact physics checks every number before anyone sees it, from a Bell pair drawn in pen to a distance-5 surface code, and from satellites in orbit tonight to a real IBM quantum computer.

What Inkubit is

You can draw a circuit on paper, photograph a whiteboard, type a problem, say it out loud or give it a paper. Inkubit turns any of these into a structured plan. SAM 3.1 finds the drawn parts of a sketch. Muse Spark reads the photo into a validated specification, writes and repairs code, plans multi-step missions and writes reports. Muse Wonder takes the long, many-step questions and reads whole papers. Muse Voice Transcribe takes speech, and Muse Image draws illustrations that are always shown next to the exact drawing.

None of these models produces a physical result itself. The results come from exact engines: density-matrix simulation with realistic noise, an independent second simulator, exhaustive search, symplectic checkers for error-correcting codes, an SGP4 orbit propagator, closed-form chemistry integrals and a minimum-weight matching decoder. These run under physical invariants and statistical tests. If a check fails, Inkubit says so: a run that cannot be repaired is shown as Not verified, and a number in a model's answer that matches no tool result is flagged.

The same principle runs through every lab. A model proposes a circuit layout, an error-correcting code, a plan or a reading of a paper. An exact method then accepts or rejects the proposal and says why. In some labs the verdict goes back to the model, which then does better: Chapter 7 shows a model that improves only when it sees exact physics' verdicts.

What makes it different

Four things set Inkubit apart from a language model put in front of a simulator, and each is measured.

  • The model never has the last word. Every model output passes a check that does not trust it: specs are validated, code is compared with an independent prediction, proposed circuits are proven equal, and numbers in reports are traced.
  • Proposals are checked, not trusted. Discovery, learning, code design and the referee are loops in which a model proposes and an exact method decides. The model supplies the ideas; a proven verdict keeps them honest.
  • It reaches real systems. An AI-discovered circuit beat the textbook circuit on a real IBM quantum computer. The satellite planner flies today's quantum-key satellites on their real orbits; the whole-paper lab reads a real 100-page paper.
  • Its own claims are held to the same rule. A test rebuilds every number in the README and the submission from its data file, and this report is generated from the same data.

The problem and the principle

Quantum programs fail silently, and language models are fluent but not exact. The answer is a division of labour: the models read, plan and propose, and exact physics decides what is true.

A wrong quantum program still runs

A reversed CNOT, or a qubit index off by one, does not crash a quantum program. It still runs and still prints a histogram; it is just the wrong histogram. On real hardware every histogram is noisy anyway, so a wrong answer can look like an ordinary bad day for the chip. Students and researchers sketch circuits and network layouts on paper long before they write code, and the step from a sketch to correct code is where the time goes. Errors also come from the notation itself: textbooks write states as kets, papers use their own diagrams, and frameworks such as Qiskit, Cirq, Quil and OpenQASM disagree on conventions such as bit order.

The obvious fix today is to ask an AI assistant. The assistant writes plausible code, explains it confidently and predicts the output. The prediction is the weak point. A model predicting a circuit's output is doing the calculation in its head, and that calculation grows exponentially with the number of qubits.

Language models are fluent, not exact

Inkubit measured this before it relied on it (Chapter 15). Muse Spark was asked to predict circuits' outcome odds on its own, the way a chat assistant answers, and was scored against exact simulation. It was exact on {{ar_tb}} textbook circuits and on {{ar_new}} new small circuits; the easy version of the claim, that chatbots get quantum circuits wrong, did not hold. On bigger new circuits of 6 to 8 qubits it was exact on only {{ar_big}}. One answer described a near-uniform distribution with full confidence and put {{ar_worst}}% of the probability in the wrong place. Nothing in the answer itself warned the reader.

The finding that shaped the design

A model's confidence says nothing about its accuracy on a problem it can't calculate. A checker that recomputes the answer exactly is not optional, and it must be independent: it must never read the model's code or reasoning, only the specification of what was meant.

The principle: the AI proposes, exact physics has the last word

Every feature of Inkubit follows one division of labour. The models do the parts that need perception, language and imagination. Exact methods do the parts that need correctness. Checks that trust neither side sit between them and the user.

Rules the app keeps

A principle only matters if the software enforces it. These rules are enforced in code and covered by tests.

  • Every model answer names its model. The badges say Meta live, Mock or Mock fallback, with the error. Offline mode never pretends to read a photo it doesn't know; it says that reading one needs the live models.
  • No faked success. The repair loop stops when the repairer returns the same code twice. After four attempts the result is labelled Not verified, and its code and counts are marked as unverified.
  • Thresholds come from statistics, not from tests. The verification bound is derived from the multinomial standard error, and it has never been loosened to make a test pass.
  • Every number is traced. In the assistant and in mission reports, each number the model writes is matched, at the precision written, against the tool results. Untraced numbers are shown as untraced.
  • Speed-ups and replays are labelled. The demo video tags any sped-up wait on screen. Micius, which re-entered the atmosphere in January 2026, flies only as a labelled replay of its 2017 experiments.
  • Our own documents are checked. tests/test_claims.py rebuilds each quoted number from its data and fails if a document says anything else.

Who it is for

The start page offers nine use cases, each with a pen sketch on paper in the hand of the sample sketches. Each opens the part of the app that does that job: sketch to code, debugging, chemistry, quantum security, optimisation, satellite networks, cryptography, real hardware and trust. Students can learn from it by drawing, educators can turn a whiteboard into a live simulation, and researchers can check a paper's numbers or a chip's behaviour. The checks are the same for everyone.
