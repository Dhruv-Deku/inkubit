Discovery: AI proposes, physics proves

Models are good at guessing structure, and exact methods are good at judging it. The discovery lab combines the two to find shorter circuits than the textbook, and the learning loop shows the model getting better only when it sees exact physics' verdicts.

The discovery lab

The task is concrete: prepare a target state on a real chip's wiring with as few CNOTs as possible. Two-qubit gates carry about fifteen times the error of one-qubit gates on today's hardware, so every CNOT saved matters. The search has three stages:

  1. Propose. Muse Spark proposes CNOT layouts under a JSON schema; pairs the chip cannot do are dropped, and a layout is credited to the model when it wins. Spanning trees of the coupling map and random layouts add more. Layouts are tried from the fewest CNOTs up.
  2. Fit. For each layout, the single-qubit rotations between the CNOTs are fitted exactly by L-BFGS with restarts on a NumPy statevector (checked against Qiskit in a test). The fit is then pruned: rotations under 1e-3 are zeroed and the rest re-fitted.
  3. Prove. A winner must reach an overlap of at least 1 − 1e-8 with the target in Qiskit's own Statevector of the rebuilt specification. The ML verifier screens the survivors, and exact noisy simulation decides between them.

Two baselines are compiled onto the same coupling map at Qiskit's highest optimisation level: the textbook circuit, and Qiskit's general StatePreparation. "Fewest found" is not a proof of minimality, and the page says so.

An AI scientist that learns under proof

The discovery lab uses the model once. The learning loop asks a sharper question: does the model get better when it sees what exact physics said about its earlier ideas? Muse Spark proposes up to four CNOT layouts per round for a target state. The exact optimiser fits each one, and Qiskit proves every layout that reaches the target. Three conditions get the same number of proposals:

  • With feedback: each round's prompt lists every earlier layout and its verdict;
  • Asked afresh: the same model, asked again each round with no history (the prompts are numbered so no answer is reused from the cache);
  • Random wiring: random allowed pairs with the same lengths as the feedback run.

What the curves show

With feedback, the best proven layout improved on all {{learn_targets}} targets ({{learn_steps}} CNOTs). Without feedback the model never improved on its first round, and it repeated itself. On the five-qubit line its first answer was already 7, so asking again could not help. Random wiring of the same lengths never reached a target at all, which shows that the model's layouts carry real structure.

The reach rates tell the other half of the story. With feedback, fewer of the model's layouts worked than without it (10–15% against 10–35%). The model aimed below its own best and missed more often, and that is how it found the shorter ones. This is the behaviour of an experimenter, not of a lookup table: with the evidence in front of it, the model takes risks. Without it, it plays safe and stays where it was.

Engineering note

The first full run died on a truncated answer. A cut-off JSON answer is a successful HTTP response and is cached like any other, so a plain retry would have returned the same truncation. The retry now doubles the token budget and marks itself, which changes the request, while the first attempt stays identical and keeps its cache entry.

AI-designed error-correcting codes

Muse Spark designs stabilizer codes, and an exact checker proves what each one can do. For hardware where phase flips dominate, it found a code that needs {{code_dz}} phase-flip errors to fail, {{code_ratio}} times the surface code's {{surface_dz}}.

Stabilizer codes in brief

A quantum error-correcting code spreads k logical qubits over n physical ones. A stabilizer code is described by n − k commuting Pauli operators, its generators, written as strings such as XZZXI. Measuring them reveals errors without disturbing the stored information. The code's distance d is the smallest number of single-qubit errors that can change the logical information without being detected. A code with d = 3 corrects any single error, and its parameters are written [[n, k, d]].

Real hardware is often biased: some qubits suffer phase flips (Z errors) far more often than bit flips (X errors). For such hardware, what matters is dZ, the smallest number of Z errors alone that defeats the code, as long as the code still corrects any single error of any kind.

An exact checker

qcanvas/codes.py checks any stabilizer code exactly, in the symplectic picture where each Pauli string is a binary vector:

  • the generators must commute (symplectic inner product zero for every pair) and be independent (full rank over GF(2)); then k = n − rank;
  • the distance is found by brute force over every Pauli error from weight 1 up: the first error that commutes with every generator but is not itself in the stabilizer group is a logical error, and its weight is d;
  • dX and dZ are the same search restricted to X-only and to Z-only errors.

Reading the result honestly

The checker proves the distances; they are facts about the generators, not estimates. Distances are not the whole story, though. How well a code performs under realistic biased noise also depends on the decoder, the circuits that measure the generators and the error rates. Q-Canvas does not yet simulate a decoder for the new code, so the claim is limited to what the checker proves. Muse Spark's own explanation of its design, "adjacent-pair X parts form a repetition code giving Z distance 9 while step-pattern Z parts keep X and Y checks distinct", is shown as the model's idea, next to the checker's verdict. The page lets anyone enter their own generators and get the same exact analysis.

Reading the literature

Muse Spark and Muse Wonder read figures and whole papers; they transcribe and never compute. Exact simulation then judges every stated number against its error bar, and the lab says which experiments the paper does not specify completely instead of guessing them.

Reproduce a figure

Upload a figure from a paper. Muse Spark transcribes the circuit as OpenQASM, which the exact parser reads, with the sketch pipeline as a fallback. It also transcribes the claimed outcome probabilities, the shot count, the hardware and the bit order. The circuit is re-run exactly and every claim is judged against an error bar:

  • with a known shot count, three standard deviations of shot noise (at least 0.01);
  • without one, 0.03 for hardware results and 0.005 for ideal ones; a hardware claim may also sit between Q-Canvas's ideal and realistic predictions;
  • if the bit order is not stated, both orders are tried, and the better fit is used and labelled as inferred.

In a live check, Muse Spark read a printed figure's circuit, all eight bar heights, the shot count and the bit order in 8 seconds, and every claim was judged within its error bar.

Reproduce a whole paper

A figure is one experiment; a paper is many. Give Q-Canvas an arXiv id or a PDF. One pass over a hundred-page paper, with Muse Wonder reading the whole PDF, proved fragile: it listed repeated runs of one Bell circuit, dropped numbers into its notes, and once returned truncated JSON. Two passes work:

  1. Find. Muse Wonder reads the whole paper and lists up to eight experiments on different circuits, each with the pages it is on.
  2. Transcribe. pypdf cuts those pages, plus the next one, into a small PDF. Muse Spark transcribes each experiment on its own, in parallel, under the figure checker's schema.
  3. Judge. Circuits go through the exact parser, and every stated probability through the figure checker's judge.

What "not reproduced" means

The two experiments not reproduced are Shor's algorithm for 15 and a quantum walk. Their stated numbers are measurements from 2018-era hardware, whose noise Q-Canvas's realistic preset does not reach. That is a statement about the preset and the old devices, not an accusation against the paper. The lab reports what it can check, with what error bars, and leaves the interpretation visible.

A silent error that a test caught

Building the whole-paper lab exposed a quiet bug elsewhere. The QASM extractor stopped at the first statement it did not recognise, so a circuit containing an opaque gate became an empty circuit. An empty circuit gives P(000) = 1, and a paper claiming a high P(000) was then "reproduced". The extractor now refuses any statement that acts on qubits and that it cannot read, and it strips comments first. A wrong reproduction is worse than an honest "cannot check", and the test suite now holds that line.
